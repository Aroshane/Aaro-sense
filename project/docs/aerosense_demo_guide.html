Demo Flow

3-Minute Live Demo Execution

Follow this precise sequence to execute a complete, reproducible end-to-end demonstration. Each step should be pre-tested before the presentation.

⚙️
Pre-flight
Pre-Demo Environment Setup
Before Presenting

Install all required Python packages and confirm the SQLite database file exists. Ensure no process is occupying ports 5001 or 8050.

pip install flask flask-cors pandas numpy scipy msgpack dash plotly scikit-learn
Port 5001 — GCS API
Port 8050 — Dash Dashboard
Port 5005 — Telemetry UDP
🚀
Step 01
Launch Flask GCS API + Dash Dashboard
~10s startup

Double-click run_aerosense.bat or run the launcher script. This frees occupied ports, boots the Flask REST API on port 5001, the Dash server on port 8050, and auto-opens two browser tabs.

python project/launcher.py
Kills existing port occupants
Opens localhost:5001 (React GCS)
Opens localhost:8050 (Dash 3D)
📡
Step 02
Start Telemetry Ground Receiver
Second Terminal

Open a new terminal and start the ground station receiver. This initializes the SQLite database schema, opens a UDP socket on port 5005, and waits for incoming binary MessagePack telemetry packets.

python project/Ground/ground_station/aerosense_ground.py
Creates aerosense.db if absent
Listens UDP:5005
LoRa COM3@115200 (optional)
🛸
Step 03
Run Live Flight Simulator
Third Terminal

In a third terminal, start the simulator. It generates real-world-mimicking telemetry packets replicating an early-morning temperature inversion scenario and broadcasts them to the ground receiver over UDP.

python project/Ground/ground_station/simulate_flight.py
Simulates temperature inversion profile
Broadcasts 65-byte MsgPack UDP
GPS + PM2.5 + BME280 + MQ-135
🖥️
Step 04
Show React GCS Cockpit — Live Console
Show to Audience

Navigate to http://localhost:5001. Show the live scrolling telemetry console. Point out how PM2.5, temperature, pressure, altitude, and GPS coordinates update dynamically. Highlight the color-coded AQI status indicator and health recommendations.

Live telemetry feed
IND-AQI color breakpoints
Health alert recommendations
🔴
Step 05
Navigate to Obstacle Radar Panel
Show to Audience

Click the Radar tab in the GCS cockpit. Show the dynamic circular proximity radar interface. Explain this panel is driven by the VL53L1X ToF laser rangefinder API — currently simulated with synthetic obstacle distances, ready for hardware plug-in.

Proximity warning zones
VL53L1X ready interface
🌐
Step 06
Show 3D Volumetric Flight Path Map
Show to Audience

Switch to http://localhost:8050 and navigate to 3D Volumetric Mapping. Rotate and zoom the interactive 3D scatter plot. Each point represents a GPS-tagged waypoint, colored by AQI severity — green for clean air through purple for hazardous pollution.

Lat / Lon / Alt coordinate space
AQI color gradient overlay
Interactive Plotly 3D scatter
📊
Step 07
Demonstrate 2D Altitude Slice Heatmaps
Show to Audience

Click 2D Spatial Slices and drag the elevation slider to 15m, 30m, 50m. Each step reveals a horizontal SciPy-interpolated heatmap of PM2.5 density — showing how pollution varies with height and where inversion layers trap particulates.

15m — ground layer profile
30m — transition layer
50m — inversion cap
SciPy cubic interpolation

Step 08
Run AI Inversion Forecast
Highlight Feature

Return to the GCS cockpit and navigate to the AI Forecast tab. Show the what-if vertical column simulator. Explain how the Random Forest model uses temperature and pressure gradients at 15m, 30m, 50m to predict future ground-level PM2.5 spikes 15–30 minutes in advance.

Random Forest / XGBoost model
DeltaT gradient features

Usage Steps

Complete Usage Guide by Role

Detailed usage walkthroughs for each stakeholder — from hardware team to evaluators and judges.

01
Flash MicroPython Firmware
Erase and flash MicroPython v1.20+ onto the ESP32-S3 DevKit using esptool.py. Use WebREPL or Thonny IDE for initial diagnostics and to upload firmware files.
→ See firmware/main.py
02
Wire Sensors to ESP32-S3
Connect BME280 via I2C (GPIO21/22), PMS5003 via UART2 (GPIO26/27), and MQ-135 via ADC with 1.8k + 3.3k resistor divider on GPIO34 to protect from 5V output.
→ See WIRING_ESP32.md
03
Configure LoRa Radio
Wire the Ra-02 SX1276 via SPI (SCK=18, MISO=19, MOSI=23, CS=5, DIO0=4, RST=14). Set frequency to 433 MHz with spreading factor 10 for maximum range.
→ See config.json
04
MAVLink GPS Bridge
Connect Pixhawk/SpeedyBee UART telemetry to ESP32-S3 UART1 (GPIO33 RX / GPIO25 TX) at 57,600 baud. ESP32 parses GLOBAL_POSITION_INT messages to obtain GPS coordinates.
→ See aerosense_esp32.ino
05
Upload Arduino C++ Build
For production, use the optimized Arduino C++ firmware. Install Adafruit BME280, Pololu VL53L1X, and Arduino-LoRa libraries. Implements 0xCA float packing for 65-byte MsgPack packets.
→ See aerosense_esp32.ino
06
Ground Receiver Hardware
Connect an Arduino Nano with SX1276 RX module to a PC USB port. The Nano decodes LoRa packets and forwards them at 115,200 baud to the Python GCS server via USB serial.
→ See aerosense_ground.ino
01
Install Dependencies
Install all Python requirements: flask, flask-cors, pandas, numpy, scipy, msgpack, dash, plotly, scikit-learn. Or pip install -r requirements.txt from the project root.
02
Launch Full Stack
Run python project/launcher.py. This frees ports 5001 and 8050, starts both servers, and opens browser tabs automatically in sequence.
03
Monitor API Endpoints
The Flask API at localhost:5001 exposes /api/status, /api/telemetry, /api/stats, /api/config, /api/mission/waypoints, /api/prediction/predict, /api/export, and /api/obstacle-avoidance.
04
Start Ground Receiver
Run aerosense_ground.py in a second terminal. It manages two concurrent threads: USB serial LoRa reader at COM3 and WiFi UDP socket on port 5005 for dual-channel ingestion.
05
Query Database Directly
Use python project/inspect_db.py to directly inspect telemetry records in aerosense.db. Useful for verifying that data ingestion is working before presenting dashboards.
06
Export Flight Data
Hit the /api/export endpoint to download all flight records as CSV or JSON for offline analysis, academic reporting, or CPCB reference calibration workflows.
01
Open Dash Dashboard
Visit http://localhost:8050. The Plotly Dash app reads directly from aerosense.db without going through the Flask API, enabling independent database access and visualization.
02
3D Scatter Plot Navigation
Navigate to 3D Volumetric Mapping. Use mouse to rotate, scroll to zoom, and double-click to reset. Each plotted point represents a GPS-tagged telemetry snapshot from the flight.
03
AQI Color Interpretation
Color scale: Green (0-50 Good) to Yellow (51-100 Moderate) to Orange (101-150 Unhealthy Sensitive) to Red (151-200 Unhealthy) to Purple (201+ Hazardous).
04
2D Altitude Slice Heatmaps
Click 2D Spatial Slices. The elevation slider applies SciPy cubic griddata interpolation to reconstruct PM2.5 concentration at any chosen altitude band (15m, 30m, or 50m AGL).
05
Live Ticker Console
The Live Ticker panel streams real-time logs of every telemetry packet received, and fires alerts when PM2.5 exceeds user-defined threshold levels.
06
Refresh Rate Control
The dashboard auto-refreshes via Dash interval callbacks. Data appears within seconds of the simulator broadcasting new packets, giving a live data experience during demos.
01
Train the Forecast Model
Run aerosense_predict.py. Trains a Random Forest Regressor on vertical column data, saves to data/aerosense_model.pkl, and prints Test MAE and Cross-Validation MAE metrics.
02
Understand Feature Engineering
Key features: temperature at 15m, 30m, 50m; pressure gradients (deltaP = P50 - P15); PM2.5 at each layer; deltaT temperature gradient; and hour-of-day for diurnal inversion context.
03
Run What-If Simulation
Use the AI Forecast tab in the React GCS cockpit. Input custom altitude layer values and click Predict to see real-time inference from the loaded .pkl model via the Flask API endpoint.
04
Interpret Feature Importance
The feature importance chart reveals which sensor reading most influences future ground-level PM2.5 forecasts — typically temperature gradient between 15m and 50m during morning inversions.
05
Calibrate with CPCB Data
Run calibrate_sensors.py with a CPCB reference CSV file to automatically compute PM2.5, PM10, and temperature offsets and write them to firmware/config.json for field accuracy.
06
Export Predictions via API
POST to /api/prediction/predict with a JSON body containing altitude-layer values. Returns predicted ground-level PM2.5 plus confidence metadata. Integrates with third-party AQI dashboards.
01
Open Mission Planner
Go to the Waypoints tab in the React GCS cockpit. The Leaflet map interface allows you to visually set a survey origin and configure grid spacing for automatic route generation.
02
Generate Lawnmower Grid
POST to /api/mission/generate with origin point (lat, lon, alt), grid dimensions (rows x cols), and lane spacing in meters. Returns a fully valid ArduPilot .waypoints file as JSON.
03
Load into ArduPilot
Export the .waypoints file and load it into Mission Planner or ArduPilot via USB. The drone executes a multi-altitude vertical profiling survey along the generated grid automatically.
04
Vertical Column Strategy
Design missions to sample at exactly 15m, 30m, and 50m AGL at each grid node. This vertical profiling strategy provides the altitude column features required by the AI inversion predictor.
05
View Active Waypoints
GET /api/mission/waypoints returns the parsed aerosense_mission.waypoints file as JSON. Each waypoint contains GPS coordinates, altitude, and ArduPilot command codes for inspection.
06
Update Device Config Remotely
Use the Device Config tab or POST /api/config to remotely update payload parameters — WiFi credentials, sensor calibration offsets, LoRa frequency — without reflashing firmware.
Evaluation

Hackathon Evaluation Criteria

Five evaluation domains used to score the AeroSense project. Each domain maps to observable, demonstrable features during the live demo.

💡
Innovation & Technical Novelty
How creatively and technically does AeroSense advance beyond existing fixed air quality monitoring approaches?
Weight25 pts
  • 3D volumetric mapping vs. fixed ground stations
  • MAVLink GPS bridge eliminates redundant hardware
  • 65-byte MsgPack compression over LoRa
  • ML inversion boundary forecasting (novel application)
  • CPCB auto-calibration pipeline
⚙️
Technical Completeness
Is the system a complete, integrated, and functional end-to-end solution with real hardware, firmware, and software all working together?
Weight25 pts
  • Dual firmware: MicroPython + Arduino C++ build
  • Multi-threaded GCS with LoRa + UDP dual ingestion
  • Flask REST API with 9 unique endpoints
  • React GCS cockpit + Plotly Dash 3D dashboard
  • Trained ML model serialized to .pkl for deployment
🌍
Real-World Impact & Applicability
Does this project solve a real, measurable environmental problem? Can it be deployed in practical scenarios beyond the lab?
Weight20 pts
  • Addresses urban vertical pollution profiling gap
  • Temperature inversion forecasting for public health
  • ArduPilot-compatible autonomous mission planning
  • Total payload cost under Rs.2,600 (deployable at scale)
  • CPCB regulatory reference calibration capability
🎨
Presentation & UX Quality
Is the project clearly communicated? Does the user interface demonstrate a polished, premium product experience for operators and judges?
Weight15 pts
  • Premium matte dark UI with neon orange accents
  • Interactive 3D Plotly visualizations
  • Live telemetry console with AQI color breakpoints
  • Radar panel and cockpit-inspired navigation
  • Slide deck covering all technical domains
🔒
Robustness & Engineering Quality
Is the code well-structured, fault-tolerant, and production-grade? Are potential failure modes handled correctly?
Weight15 pts
  • try-finally port cleanup in launcher.py
  • Parameterized SQL queries (no injection risk)
  • Thread-safe dual-channel ingestion with socket exception handling
  • Resistor divider protection for MQ-135 on ESP32 ADC
  • Graceful degradation without LoRa (WiFi UDP fallback)
